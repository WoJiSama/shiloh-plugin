# 阶段 3：生图完整链路与模型网关

前置回滚锚点：`a66d199`（阶段二）。直接 main，独立提交；本阶段不单独部署生产。

## 实际接线

QQ `BananaTool.performDraw` 与控制台绘图 HTTP 入口复用严格 TS `ImageService`。生成、编辑、multipart、多图响应、候选回退、资源下载和尺寸校验由共同实现处理；Gemini 聊天式生图保留独立服务方法。QQ 适配器继续取第一张并交原投递接口；控制台保留多图及历史。原重复请求/解析方法已删除或变成明确委托。

候选配置归一化、渠道选择、画幅策略、图片头解析、结果抽取、参考图策略、任务分类、请求保护、失败分类、multipart 编码均迁入 TS。Grok 请求画幅与返回尺寸继续比对，不通过缩放或裁切假装上游遵守画幅。

模型 `YTapi` 全部路由、强制工具调用边界、文本后端回退、任务模型推理档、可选参数兼容与响应处理迁入带显式端口的执行器。网关请求构造、重试策略、旁路模型传输、连通性探针、失败诊断和 Unicode/思考标记处理均迁入 TS。模型远程响应按声明结构校验；未知提供商字段保留 unknown，不关闭 strict。余额不足与频率限制分开，余额不足不重复重试。HTTP、网络与 JSON 失败带实际渠道及模型，展示前脱敏。

## 行为验证边界

测试使用真实 emitted ESM。控制台子进程与本地假渠道验证多图、质量、模型和原始字节；QQ 子进程导入真实 BananaTool，只替换缺失的三个 Yunzai 宿主模块，验证 performDraw 经 ImageService 到投递边界。没有调用真实付费模型，也没有给真实 QQ 群发测试消息。

取消覆盖候选切换、输出下载、控制台参考图下载和模型响应正文。QQ 旧参考图 URL 续期转换器尚不能中断已经进行的下载，服务在其前后检查取消，不能据此宣称 QQ 全链路主动取消已完成。队列、发送、持久化和 QQ 宿主 API 适配继续按阶段五/七处理；模型语义路由辅助通过具名端口注入，阶段六迁移其业务。BananaTool 和 console/server 仍计入业务 JS，不因部分迁移改列兼容入口。
