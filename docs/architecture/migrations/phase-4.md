# 阶段 4：配置仓库、权限与公共契约

前置回滚锚点 `628fdeb`。本阶段直接主干独立提交，不单独部署。

四条 YAML 写入路径 configStore/configWriter/model配置管理/console 全部接入 ConfigRepository。仓库用相同文件目录锁串行化跨进程读改写，以文件内容 SHA256 执行可选 CAS，临时文件 fsync 后原子替换，保留上版备份。读取或修改非法 YAML 时拒绝覆盖。锁超时报具体路径和 owner；不按时间猜测抢锁，异常退出后的遗留锁需确认原进程不存活后人工处理。备份恢复与锁处理是两件事。

JSON 群思考设置保持原路径和格式，使用相同文件锁与原子写入能力；群维度更新在锁内重新读取，避免两个进程更改不同群互相覆盖。开启、关闭、状态三个命令均只允许主人或群主，群管理员无额外授权。

公共 ConfigSchemaItem 契约用于全部配置 schema 与控制台。原共享 schema、Guoba schema 构造、渠道配置规范化和面板保存/探针业务已迁 TS。必要旧路径为薄导出或受哈希审计的组合入口。控制台保留字段级 HMAC 页面 revision，底层另用文件快照 revision 防止读取与写入间竞争，冲突 HTTP 409。凭据保留/替换/清除、稳定渠道 ID、未知字段保留均有回归；显式清空额外尺寸同步到旧字段，不再复活旧值。Guoba 按稳定 ID 或唯一渠道身份合回未提交扩展字段，不按位置绑定未知字段。

配置默认合并改为保留未知用户字段与显式空值；原旧测试的“裁掉未知键”预期相应更新。namedConfig 缺失文件现在使用仓库默认文档，而非旧 ENOENT。监听器新增 stopWatch 清理防抖与 watcher；日志不输出配置值。

并发证据：4 个独立进程执行 48 次 YAML 更新无丢失，2 个独立进程执行 40 次不同群 JSON 更新无丢失。控制台真实 HTTP 测试覆盖过期页面冲突、渠道重排和隐藏扩展字段/凭据保留。没有修改线上配置。
