前置回滚锚点 `d1c7d8b`。本阶段独立主干提交，最终发布闭环前不部署生产。

迁移完整消息管道：事件快照、串行队列/信号量、心跳租约、Redis任务仓库、处理状态机、运行时装配、投递网关、出站仲裁/限流、媒体outbox/资源缓存、风险监听、视频缩略图、近期记录与NDJSON归档、健康报告与收发统计。控制台任务查询契约亦迁入TS，页面可查看sending/uncertain。

关键行为修复：
- 任务失去租约后不能提交完成/失败或继续发送；持久任务读入执行前验证实际shape。
- 发送前持久化sending，成功后状态写入失败不能触发重复投递；恢复sending转uncertain等待人工核对。
- 回执缺失或网络结果不明，禁止自动尝试备用文件上传。明确拒绝且确认未发送才沿原策略回退。
- 转发按实际节点数量分批，每批最多100；未知回执不计成功、不自动重试后续份。
- 装配中途失败、启动失败、重复安装及禁用统一逆序清理；dispose幂等，异步清理错误不成为未处理拒绝。

验证使用fake Redis/宿主端口和真实临时NDJSON，没有向真实群发消息。400条归档加标题形成100/100/100/100/1，验证顺序与全量保留。近期消息并发去重、损坏记录、配置热更新、完整正文超时等均加载emitted模块测试；残余apps命令解析测试在入口迁移阶段替换。

兼容边界：现有Redis key/NDJSON目录保持。归档按群号或私聊用户号共享，多机器人同群以及相同私聊用户共享旧记录，不宣称机器人级隔离。旧业务消费的媒体富化/宿主调用通过明确端口连接，所属业务后续阶段迁移。新增sending/uncertain状态与旧worker行为不同，回滚前必须停worker并保留这些任务，不允许旧worker直接自动恢复未知投递记录。
