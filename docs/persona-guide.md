# 人设卡写作规范（persona-guide）

> 适用对象：`config/persona-library.yaml` 里的人设条目与控制台「人设与绑定」页编辑器。
> 结构参考 qq-bridge 的 roles/ 规范（两层提示词分离 + 对照式示例 + AI 味黑名单），按 shiloh 的字段结构落地。

## 一、两层提示词：人设卡只写"你是谁"，不写"怎么干活"

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **人格层**（人设卡） | persona-library 条目 / message.yaml 的 persona 段 | 你是谁：身份、性格、说话风格、反应模式、梗、雷点、示例、禁用词 |
| **行为层**（协议） | 代码内置（主链路身份原则 / 仿真协议），不可被人设覆盖 | 怎么干活：工具用法、分条、唤醒潜水、记忆卫生、语气分寸红线 |

**不要在人设里写工具用法、分条方式、唤醒规则**——行为层每条消息都会注入，写了只会占预算还会打架。人设管"态度和措辞"，行为层管"机制"。

## 二、字段怎么写（按效果排序）

### 最有效的三个字段（优先写好）

1. **`samples`（回复示例，对照式）**——直接钉死语气和长度，比一切形容词都管用：
   ```yaml
   samples:
     - "群友：我今天去喝酒了 → 你不要：酒要适量哦，注意身体～ → 你可以：上班也能喝 少喝两杯就行了"
     - "群友：今天好累 → 你不要：辛苦啦，明天又是元气满满的一天！ → 你可以：累了就睡 醒了继续累"
   ```
   每条 = 场景 + 错误示范 + 正确示范。示例只示范**语气和长度**，模型不会照抄台词。

2. **`reactions`（场景化反应模式）**——把"傲娇""嘴硬"这种形容词翻译成可执行的反应：
   ```yaml
   reactions:
     - "被夸：嘴硬但不真推开，如'哼，才不是特意帮你呢'"
     - "被叫外号：否认但不生气，如'才不胖'"
     - "被怼：优先顶回去，不解释不找补"
     - "发现刚才白心疼了对方：会炸毛，如'？白心疼了'"
   ```

3. **`blacklist`（禁用词句）**——**出站确定性拦截**（代码层真的删掉，不只是提示）：
   ```yaml
   blacklist:
     - "本小姐"
     - "保证解压"
     - "强烈推荐"
   ```
   系统另有内置 AI 味词表（"希望这个回答对你有帮助/作为AI/这是个好问题/综上所述"等），无需重复写。

### 基础字段

- `identity`：一句话身份内核（性格底色），别写成履历。
- `tone` / `speechStyle`：语气与说话习惯。**写"不要什么"通常比"要什么"更有效**（不要总结、不要升华、不要客服腔）。
- `preferences` / `boundaries`：稳定偏好 / 雷点与底线。
- `moods`：情绪波动档位（可选）。
- `notes`：补充设定。

## 三、预算与卫生

- 人设随**每条消息**注入，全字段合计建议控制在 **2000 字符内**（samples 最多 6 条会被截断）。
- `blacklist` 每条 ≥2 字符才会生效，最多 40 条。
- 人设描述"你是谁"，**不证明你做过什么**：缺事实不要补成确定经历（行为层身份原则会兜底）。

## 四、改完怎么生效

- 控制台保存 / 手改 persona-library.yaml：**下一条消息即生效**（人格层每条消息注入，无需重启）。
- 换人设不清记忆：好感度、梗库、印象是按群沉淀的，属于"这个群的经历"，跟人设切换无关；想清空用 `.仿真 重置`（也只清会话历史）。
