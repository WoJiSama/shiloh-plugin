# 控制台群管理

2026-10-16，本地实现与定向验收完成，尚未提交、推送或部署。本轮没有发送群测试消息、调用外部模型或修改生产配置。

## 入口和操作

- 侧栏「日常运营 → 群管理」：`#/group-admin`，支持群名搜索、群选择和直接输入群号。
- 「默认策略」：`#/group-admin?scope=defaults`，配置各模块总开关及默认参数。
- 「按群配置」：`#/group-admin?group=<群号>`，配置入群验证、广告与刷屏、欢迎与退群通知，以及本群通知 QQ。
- 群聊列表和详情均可进入本群管理，群管理可返回对应群聊详情。已配置但尚无活动的群也会出现在列表中。

字段可选择继承或本群自定义，也可逐项恢复默认。整群恢复保留各模块的本群启用状态。保存只提交本次变更；切群、离开、保存冲突和请求期间继续编辑均有草稿保护。

## 配置和兼容

原 `groupGuard`、`groupModeration`、`groupNotice` 提供默认参数，三个原有 `enabled` 仍是全局总开关。每个群需要单独启用对应能力，本群启用不能绕过总开关。原有机器人和群管理员权限检查继续适用。

本群覆盖存储于 `pluginSettings.groupAdmin.overrides`，字段缺省时继承默认值。`false`、空文案和空名单均可明确保存，广告阈值及处罚动作按子字段继承。本群通知名单与全局通知 QQ 合并，仅通知明确配置的接收人。

旧锅巴的启用群名单、通知模板和通知名单继续生效。恢复字段时同步清理本群旧值；兼容带空格的群号、旧 `group_id` / `group` 别名及重复表单记录。欢迎或退群开关单独恢复默认时，保留原文案并解除旧模板隐式开启通知的行为。未知扩展字段、其他群配置与未改动 YAML 注释保留。

默认策略使用 `GET/PUT /api/config/groupAdmin`；单群使用 `GET/PUT /api/groups/:id/admin`，PUT 内容为 `{ revision, values, resets }`。新接口必须提交 revision，本群或默认策略变化返回 409，其他群保存不会使本群草稿版本失效。落盘另有文件级版本检测。

保存后，后续群事件读取新配置。进行中的验证保留原题目和截止时间，关闭验证后不再执行超时处理。保存不会重启服务。
